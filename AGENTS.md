# Wanderlust

Single-page travel landing site. The only route is `/`, and `src/app/page.tsx` currently renders an empty fragment — design work is in progress. Hero art and logos live in `public/assets/` and are served from `/assets/...`.

`README.md` is stale create-next-app boilerplate (mentions Geist fonts and an `app/` root that don't exist) — trust the code, not the README.

Design tokens already in place — reuse them instead of inventing new ones:

- Brand blue `--brand: #15a1bf` (sampled from the logo) is mapped to `bg-brand` / `text-brand` / `text-brand-foreground` in `src/app/globals.css`.
- `font-display` (Cormorant Garamond, loaded as the `--font-cormorant` variable in `src/app/layout.tsx`) is the heading face; body/nav use Arsenal.
- `public/assets/Wanderlast.png` is the blue logo, `Wanderlast-1.png` the white one; `public/assets/Banner.png` is the hero photo (1440×746, already darkened — no extra overlay needed).

## Commands

- `npm run dev` — Turbopack dev server at `localhost:3000`. If it reports an existing server, reuse it (PID/URL in `.next/dev/lock`) instead of starting/killing another.
- `npm run build` — production build; also runs the TypeScript check and prerenders routes.
- `npm run lint` — runs ESLint directly (`next lint` was removed in Next 16).
- `npx tsc --noEmit` — fast type check without a build.
- No test runner or CI is configured.

Verified lint baseline: `npm run lint` exits 1 with two `react-hooks/set-state-in-effect` errors in generated files (`src/components/ui/carousel.tsx`, `src/hooks/use-mobile.ts`). Don't treat them as regressions; don't rewrite those files unless the task involves them.

## Framework constraints (`next.config.ts`)

`cacheComponents`, `partialPrefetching`, and `reactCompiler` are all enabled:

- Uncached data (`fetch`, `cookies()`, `headers()`) outside `<Suspense>` fails prerendering/build. Fix with a `<Suspense>` boundary, `"use cache"` + `cacheLife()`, or `export const instant = false` on the segment.
- `partialPrefetching` only prefetches the static App Shell; use `<Link prefetch={true}>` when a destination needs URL-specific (`params`/`searchParams`) data.
- `params`, `searchParams`, `cookies()`, `headers()` are async. Type pages/layouts with the generated globals (`PageProps<'/route'>`, `LayoutProps<'/'>`) instead of hand-writing prop types; run `npx next typegen` to regenerate them.
- Next 16 uses `proxy.ts`, not `middleware.ts`.
- `next/image`: the `priority` prop is deprecated in Next 16 — use `preload` (or `loading="eager"` / `fetchPriority`) instead.

## UI components

- `src/components/ui/*` is generated by shadcn with the `base-nova` style on **Base UI**, not Radix: primitives come from `@base-ui/react/*` (newer families from `@shadcn/react/*`). Compose with the `render={<Component />}` prop — there is no `asChild`. Style interaction state with `data-open:`, `data-closed:`, `data-checked:`, `data-pressed:` variants, not `data-[state=...]`.
- Import `cn` from `"cn"` (the `cn` package replaces clsx + tailwind-merge), as every generated component does. `@/lib/utils` only re-exports it.
- ~63 components are already vendored in `src/components/ui/` — check there before writing a primitive from scratch.
- Add components with `npx shadcn add <name>` and check current APIs with `npx shadcn docs <component>`. Don't paste Radix-era snippets from older shadcn docs.
- Don't bulk-reformat `src/components/ui/*`: those files are semicolon-free while `src/app/*` uses semicolons, so whole-file formatting creates noisy diffs.
- Tailwind v4 is CSS-first: tokens/variants live in `src/app/globals.css` (`@theme inline`, `--primary`, ...). There is no `tailwind.config.*`; don't add one.
